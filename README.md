你要搭建一套名为MetaInfer的大模型SKILL，该SKILL由一系列子SKILL组成，用于实现从零编写各种各样大模型的精简高效推理框架，调试现有知名开源推理框架（如VLLM、SGLANG）并在其中移植接入新模型，以及进行框架中各个环节推理算子的GPU程序编写、优化工作，总之，这是一个工具包类型的SKILL集合。

SKILL具有3个主要的入口技能：

/metainfer-gen-infer-framework: 给定需要的推理框架需求，定制一个全新的，针对单一模型的推理框架。
/metainfer-opt-kernel: 给定需要的推理算子描述，然后针对特定的平台、算子类型、输入参数尺寸等，编写并优化GPU算子
/metainfer-port-model: 给定目标推理框架（如vLLM或SGLang）、目标硬件平台和目标模型，在指定框架中加入对指定模型的支持。

上述入口技能要先以提问的方式确定需求，需要实现一个可以添加提问用户问题的框架。

由于上述3个技能都会是long-running的技能，可能连续迭代数十轮，持续若干天，因此需要提供一个可以实时查看任务状态的Web GUI，该GUI由前端HTML页面和一个临时启动的Python后端来实现，由Pytorch后端收集各个子Agent的执行状态，展示在前端界面上。需要在上述3个技能入口部分都加入启动这个状态展示服务的功能。
  - 这个服务需要保持长期活跃，不能因为中间错误而退出。同时，该程序需要具备检测子Agent是否任务全部完成的功能，能够在Agent退出后，该后端任务也退出，不能导致长期的资源占用或HTTP端口占用等。如果两个状态服务实例启动，需要给出人类友好的提示，告知目前仍有其他实例在运行。

  - 需要设计一套基于文件系统的任务管理和进度追踪方式，形成一份各个子Agent可以读懂的规范，这个规范也是一个技能，要求各个子Agent在工作的过程中按照这个技能来同步自己的当前工作任务列表，以及进展情况，包括输出的统计数据、实验数据结果等。这些数据以什么格式（包括但不限于例如迭代轮次、Agent的名字等等）组建成文件目录保存在文件系统中，并由状态服务来读取收集这些数据，从而展现结果。
    - 规范中需要包含如何使用基于文件的任务列表机制。将任务分为如下几个list： ToDo、Running、Done、Archived
      - ToDo列表按照优先级排列。优先级最高任务放在最前面。
      - Running列表表示当前正在运行的任务，一个任务可以从ToDo中移除，然后加入Running。
      - Done列表放置已经完成的任务，通过追加的方式，将最新完成的任务存放在后面。一个任务可以从Running中移除，然后加入Done。
      - Archived列表表示ToDo中一些认为已经没有必要再参与实验，可以被排除掉的任务，仅用于归档。一个任务可以从ToDo中移除，然后加入Archived。
      - 可以看到，上述任务转换流程，本质上是一个状态机。为了保证状态机的状态不出现不一致，需要保证修改是原子的，各个技能可以确定、正确的修改这些列表，因此需要使用确定性的脚本来实现对列表的编辑。因此，需要向编程Agent注册专用的ToolCall，当需要更新上述列表时，使用ToolCall来修改。
        - 工具脚本提供几个必要操作：Add New Tasks、Mark Done、Start New Task、Mark Archived
